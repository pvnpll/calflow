# Landing Page Specification

Build a premium, production-quality landing page for **CalFlow**, an AI-powered personal nutrition and health tracking platform.

## Goal

Create the public homepage users see when they first visit CalFlow.

The landing page should clearly communicate:

- What CalFlow is
- Why it is different from ordinary calorie trackers
- How AI works inside CalFlow
- ChatGPT + Claude MCP integration
- CalFlow's built-in AI assistant
- Nutrition tracking
- Water and weight tracking
- Nutrition insights and analytics
- Personalized recommendations
- The overall CalFlow ecosystem

The visitor should understand the product within 10 seconds and feel that CalFlow is a modern AI-first product rather than another basic calorie-counting app.

Do NOT make it look like a generic SaaS template.

---

# Product Positioning

Primary message:

**Your nutrition. Understood.**

Alternative supporting message:

**CalFlow turns what you eat into a living picture of your nutrition — and tells you what to do next.**

CalFlow is not just a food diary.

It combines:

**Tracking + AI + Insights + Recommendations + Automation**

The core concept:

```text
You eat
   ↓
CalFlow understands it
   ↓
Nutrition is tracked
   ↓
Your history builds up
   ↓
AI finds patterns and gaps
   ↓
CalFlow tells you what to do next
```

# Visual Direction

Design a premium, minimal, modern health-tech interface.

Think:

- Apple-level simplicity
- Linear-style polish
- Modern AI product aesthetics
- Clean typography
- Lots of whitespace
- Subtle gradients
- Soft cards
- Smooth animations
- Excellent mobile experience

Avoid:

- Generic stock photos
- Fitness-model imagery
- Excessive green "health app" styling
- Cartoon food illustrations
- Overly colorful dashboards
- Excessive rounded cards everywhere
- Fake statistics
- Fake testimonials
- Fake customer logos

The product UI itself should be the main visual.

Use screenshots/mockups of CalFlow's actual dashboard and AI interactions wherever possible.

Color system should be derived from the existing CalFlow application if it already has a design system. Do not create an unrelated visual identity.

# IMPORTANT PRODUCT RULES

The landing page must accurately represent the current CalFlow product.

Do not advertise features that are not implemented.

Where an integration is still experimental, label it appropriately.

Do not claim medical diagnosis or treatment.

Use language such as:

- "nutrition estimate"
- "logged intake"
- "below your target"
- "AI-generated insight"

Avoid:

- "detects deficiencies"
- "diagnoses nutritional problems"
- "guarantees health outcomes"

---

# TECHNICAL REQUIREMENTS

Use the existing CalFlow stack.

Do not rewrite the existing application architecture.

Use:

- Next.js
- TypeScript
- Tailwind CSS
- shadcn/ui where appropriate
- Existing CalFlow design system
- Existing authentication
- Existing API
- Existing Supabase setup

The landing page should be publicly accessible without authentication.

The actual dashboard should remain behind authentication.

Suggested routes:

```text
/
    Landing page

/login
    Authentication

/dashboard
    Existing CalFlow application
```

CTA behavior:

**Get started → /login or existing signup flow**

**Log in → existing login**

---

# RESPONSIVE DESIGN

Mobile-first.

The mobile version must feel intentionally designed rather than being a desktop page squeezed into a phone.

Prioritize:

- Hero readability
- Large CTA
- AI conversation previews
- Nutrition dashboard cards
- Water button
- Insights
- Smooth vertical storytelling

On desktop, use wide compositions and dashboard mockups.

On mobile, stack sections naturally.

---

# ANIMATIONS

Use subtle high-quality animations.

Examples:

- Hero dashboard numbers animate into place
- Nutrition progress bars animate on entry
- AI conversation messages appear sequentially
- Insight cards fade/slide into view
- Charts animate when entering viewport
- Navigation changes subtly on scroll
- Cards have restrained hover interactions

Do not over-animate.

The product should feel calm, intelligent and trustworthy.

---

# PERFORMANCE

The landing page must be fast.

Avoid unnecessary heavy libraries.

Use:

- Lazy loading for below-the-fold visuals
- Optimized images
- CSS animations where possible
- Minimal JavaScript
- Proper metadata
- SEO-friendly semantic HTML

The page should score well on Lighthouse.

# FINAL DESIGN PRINCIPLE

The landing page should tell one continuous story:

**I eat → CalFlow understands → CalFlow remembers → CalFlow analyzes → CalFlow advises.**

The visitor should finish the page understanding that CalFlow is not merely:

"another calorie tracker."

It is:

**an AI interface for understanding your nutrition.**

Build the page using the actual CalFlow product UI wherever possible so that the landing page feels like a window into the real product rather than a marketing mockup.
